REQUIREMENTS
------------
- Linux (Ubuntu/Debian recommended)
- Docker
- Docker Compose
- A DuckDNS account (with a registered subdomain and API Token)
- A GitHub Personal Access Token (boosts API limit from 60 to 5,000 requests/hour)
  Create one at: https://github.com/settings/tokens
  No scopes needed — leave all checkboxes unchecked.


STEP 1 — Clone the repository
------------------------------
    git clone https://git.mif.vu.lt/juto2015/micac_soa_2026_sh.git
    cd micac_soa_2026_sh


STEP 2 — Configure Environment Variables
-----------------------------------------
Create a `.env` file in the root of the project:

    GITHUB_TOKEN=your_github_personal_access_token
    ALLOWED_ORIGINS=https://your-subdomain.duckdns.org:14361
    DUCKDNS_TOKEN=your_duckdns_token_here
    DOMAIN=your-subdomain.duckdns.org
    EMAIL=your-email@example.com

*(Note: Replace the domain, token, and email values with your actual DuckDNS configurations.)*


STEP 3 — Start the Docker Stack
--------------------------------
Navigate to the deployment directory and start the services using Docker Compose:

    cd source_code/deployment
    docker compose up --build -d

This command will:
1. Build the backend and frontend containers.
2. Spin up Certbot to authenticate via DuckDNS and generate a Let's Encrypt SSL certificate.
3. Launch Nginx as a secure reverse proxy once SSL certificates are ready.


STEP 4 — Verify the services are running
------------------------------------------
Check the status of the Docker containers:

    docker compose ps

Verify container logs to trace any setup issues:

    docker compose logs -f


STEP 5 — Use the tool
-----------------------
Open your browser and navigate to:

    https://your-subdomain.duckdns.org/

Paste a public GitHub repository URL and click "Analyze Repository".

Example URLs to try:
    https://github.com/axios/axios
    https://github.com/boto/boto3
    https://github.com/ansible/ansible

The tool will:
  1. Fetch the repository's dependency file (requirements.txt, package.json, etc.)
  2. Check each dependency for known CVEs via the OSV database
  3. Analyse package vitality (last commit date, contributors, open issues)
  4. Return a risk score (0-100+) per dependency and a final grade (SAFE / WARNING / DANGEROUS)


STEP 6 (Optional) — Use the API directly
------------------------------------------
The Scanner API has interactive documentation available at:

    https://your-subdomain.duckdns.org/api/docs

Available endpoints:
    POST /scan          Run a CVE-only scan
    POST /zombie-scan   Run the full Zombie Package analysis (recommended)
    GET  /report        Return the last saved CVE report
    GET  /zombie-report Return the last saved Zombie Report
    GET  /health        Health check

Example with curl:

    curl -X POST https://your-subdomain.duckdns.org/api/zombie-scan \
         -H "Content-Type: application/json" \
         -d '{"repo_url": "https://github.com/axios/axios"}'


TROUBLESHOOTING
---------------
- GitHub rate limit errors (HTTP 403)
    -> Add or update the GITHUB_TOKEN inside `.env` and restart:
       docker compose down && docker compose up --build -d

- SSL Verification/Certbot issues
    -> View Certbot logs specifically:
       docker compose logs certbot

- Restart/Rebuild stack after changes
    -> Rebuild all services:
       docker compose up --build -d

- Stop the Stack:
    -> Stop and remove all containers:
       docker compose down
